In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the system divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory layout allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which typically stores the key and value vectors for a fixed number of tokens, often referred to as the page size or block size. For instance, if the page size is set to 16 tokens, a single page in the KV cache will hold the key and value tensors for 16 consecutive tokens. The choice of page size is a critical design parameter that involves a trade-off between memory overhead and management complexity. A smaller page size, such as 1 or 4 tokens, provides finer granularity, which minimizes the amount of wasted memory at the end of a sequence (internal fragmentation). However, a smaller page size increases the metadata overhead required to track the mapping between logical pages and physical memory blocks. The inference engine must maintain a table that maps each logical page index to a physical memory address. If the page size is too small, the number of entries in this mapping table grows exponentially with the sequence length, potentially consuming a non-trivial portion of the GPU’s limited memory or CPU memory if the table is offloaded. Conversely, a larger page size, such as 32 or 64 tokens, reduces the metadata overhead and simplifies the memory allocator, but it increases the likelihood of internal fragmentation. If a sequence ends in the middle of a page, the remaining slots in that page are wasted. Therefore, most production-grade inference engines adopt a middle ground, often using a page size of 16 tokens, which strikes a balance between acceptable fragmentation and manageable metadata costs.

The allocation strategy for these pages is dynamic and demand-driven. When a new request is initiated, the inference engine does not pre-allocate memory for the maximum possible sequence length. Instead, it allocates pages only as the model generates new tokens. This lazy allocation strategy is crucial for supporting variable-length sequences and for maximizing the number of concurrent requests that can be served within the fixed GPU memory budget. The memory allocator maintains a free list of available physical pages. When a sequence requires a new page, the allocator pops a page from the free list and updates the logical-to-physical mapping table for that sequence. This process is analogous to how an operating system allocates virtual memory pages to a process. The key advantage here is that the physical memory layout does not need to be contiguous for a single sequence. A single logical sequence can be scattered across non-contiguous physical memory blocks. This non-contiguity is handled transparently by the attention kernel, which is designed to gather the key and value vectors from their respective physical locations. Modern GPU kernels, such as those implemented in FlashAttention or PagedAttention, are optimized to handle this scattered memory access pattern efficiently, ensuring that the performance penalty of non-contiguous memory access is minimized.

Eviction and defragmentation are essential components of the paged KV cache lifecycle, particularly in scenarios where the total memory demand exceeds the available GPU memory. In a single-GPU inference engine, the memory is a fixed resource, and the system must decide which sequences to keep in memory and which to evict when the memory pressure becomes too high. The eviction policy is typically based on the least recently used (LRU) principle or a priority-based scheme that considers the importance of the request. When a sequence is evicted, its associated physical pages are returned to the free list. However, unlike traditional memory management, the paged KV cache does not require defragmentation in the traditional sense of moving data to create contiguous blocks. Because the attention kernel can handle scattered memory, there is no need to compact the memory to maintain contiguity. This is a significant advantage over contiguous KV cache implementations, which suffer from external fragmentation as sequences of varying lengths are allocated and freed.
