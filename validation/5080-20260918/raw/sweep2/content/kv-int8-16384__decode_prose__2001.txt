In the high-stakes domain of large language model (LLM) inference, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As models scale to billions of parameters, the sheer volume of intermediate states required to maintain context during autoregressive generation can quickly exhaust the limited High-Bandwidth Memory (HBM) available on a single GPU. Traditional inference engines often allocate a contiguous block of memory for the KV cache of each active sequence, a strategy that leads to significant memory fragmentation and underutilization. This is where the concept of a paged KV cache, pioneered by systems like vLLM, becomes essential. A paged KV cache decouples the logical view of the cache from its physical storage, allowing the inference engine to manage memory in discrete, fixed-size units known as "pages." This mechanism is analogous to virtual memory management in operating systems, where physical RAM is divided into pages and mapped to virtual addresses, thereby enabling non-contiguous physical memory to be presented as a contiguous logical space to the application.

The fundamental unit of this system is the KV page, which stores the key and value vectors for a specific block of tokens. The sizing of these pages is a critical architectural decision that directly impacts both memory overhead and computational efficiency. Typically, a page size is chosen to be a multiple of the number of attention heads or a divisor that aligns well with the GPU’s memory hierarchy and tensor core operations. For instance, if a model has 32 attention heads and a head dimension of 128, a page might be sized to hold the KV states for 16 or 32 tokens. This alignment ensures that when the GPU’s tensor cores perform the matrix multiplications required for attention, the data access patterns are coalesced and efficient. If the page size were too small, the overhead of managing a large number of page table entries would increase, and the GPU might suffer from increased instruction overhead due to frequent context switches between memory blocks. Conversely, if the page size is too large, the granularity of memory allocation becomes coarse, leading to internal fragmentation where the last page of a sequence may be only partially filled, wasting valuable HBM capacity. Therefore, the optimal page size strikes a balance between minimizing the metadata overhead of the page table and maximizing the utilization of physical memory pages, often determined empirically based on the specific model architecture and the typical sequence lengths observed in the workload.

Page allocation in a single-GPU inference engine is managed by a central memory allocator that maintains a free list of available physical pages. When a new sequence is initiated or an existing sequence grows, the engine requests a new page from the allocator. Unlike traditional contiguous allocation, this new page does not need to be physically adjacent to the previous pages of the sequence. Instead, the logical sequence is represented by a page table, which is a mapping from logical page indices to physical page indices. This indirection allows the physical memory to be fragmented without impacting the logical continuity of the KV cache. The attention kernel, which is the computational heart of the transformer block, is modified to be "paged-aware." Instead of reading from a single contiguous memory buffer, the kernel iterates over the page table for the given sequence, fetching the KV data from the scattered physical locations. Modern GPU kernels, such as those implemented in FlashAttention or PagedAttention, are optimized to handle this indirection efficiently. They often use vectorized loads and store operations to fetch data from multiple non-contiguous pages in parallel, leveraging the high memory bandwidth of the GPU to mitigate the latency costs associated with random memory access patterns. This approach ensures that the computational throughput remains high even when the physical memory is fragmented, as the GPU’s memory subsystem is designed to handle high-concurrency access patterns.

Eviction and defragmentation are the mechanisms that allow the inference engine to reclaim memory from finished sequences and optimize the layout of active sequences. When a sequence completes its generation, its associated pages are marked as free and returned to the global free list. However, simply returning pages to a free list does not solve the problem of external fragmentation, where free pages are scattered across the memory space, making it difficult to allocate large contiguous blocks if needed for other purposes, such as loading model weights or handling bursty workloads. To address this, advanced inference engines employ defragmentation strategies. One common approach is "page compaction," where the engine periodically moves active pages to the beginning of the memory space, consolidating free space into a single large contiguous block at the end. This operation, while computationally expensive due to the data movement required, is typically performed during idle periods or when the fragmentation level exceeds a certain threshold. Another strategy is "lazy defragmentation," where the allocator prioritizes the reuse of recently freed pages, assuming that the working set of active sequences will remain relatively stable.
