In the high-stakes domain of large language model (LLM) inference, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As models scale to billions of parameters, the sheer volume of intermediate states required to maintain context during autoregressive generation can quickly exhaust the limited High-Bandwidth Memory (HBM) available on a single GPU. Traditional inference engines, which allocate contiguous memory blocks for the KV cache of each active sequence, suffer from severe internal fragmentation. This occurs because the length of the generated sequence is unknown a priori; a sequence that starts with a short prompt may grow to thousands of tokens, requiring the system to either pre-allocate massive buffers (wasting memory) or perform costly reallocation and copying operations (wasting compute and latency). Paged KV cache, a technique pioneered by the vLLM project and inspired by the operating system concept of virtual memory paging, fundamentally restructures how this memory is managed. Instead of treating the KV cache as a monolithic, contiguous array, the system divides the GPU memory into fixed-size blocks, or "pages," and maintains a logical-to-physical mapping table for each sequence. This abstraction allows the inference engine to allocate memory in discrete chunks, ensuring that the physical memory utilization remains close to 100% regardless of the varying lengths of active sequences, thereby eliminating the internal fragmentation that plagues traditional approaches.

The core mechanism of paged KV cache relies on the concept of a "page table" that resides in the CPU or GPU memory, mapping logical token indices to physical memory block indices. When a new sequence is initiated, the inference engine does not reserve a large contiguous block of memory. Instead, it allocates a small number of initial pages, typically sized to accommodate the prompt length or a small buffer for the first few generated tokens. As the model generates new tokens, the engine checks if the current logical page is full. If it is, the system allocates a new physical page from a global free list and updates the page table to point the next logical token to this new physical location. This process is analogous to how an operating system manages virtual memory for processes, where the page table allows the hardware to access non-contiguous physical frames as if they were contiguous. The size of these pages is a critical hyperparameter that dictates the granularity of memory management. A common page size is 16 tokens, though this can vary based on the model architecture and the specific GPU memory layout. The choice of page size involves a delicate balance: smaller pages reduce external fragmentation (the waste of memory at the end of a sequence that does not fill a page) but increase the overhead of maintaining the page table and the frequency of memory allocation operations. Larger pages reduce the metadata overhead and the number of entries in the page table, which is beneficial for GPU kernel efficiency, but they increase the potential for internal fragmentation if a sequence ends mid-page. In practice, a page size of 16 or 32 tokens is often optimal, as it aligns well with the vectorization capabilities of modern GPUs and keeps the page table size manageable relative to the total number of active sequences.

The management of these pages extends beyond simple allocation to include sophisticated eviction and defragmentation strategies, which are essential for maintaining high throughput in a multi-tenant or high-concurrency environment. In a single-GPU inference engine, the total HBM capacity is fixed, and the KV cache for all active sequences must fit within this limit. When the free list of physical pages is exhausted, the engine must decide which existing sequences to evict to make room for new requests. This decision is typically governed by a priority-based or least-recently-used (LRU) policy, where sequences that have been idle for the longest time or have the lowest priority are selected for eviction. Upon eviction, the physical pages associated with the sequence are returned to the free list, and the corresponding entries in the page table are invalidated. However, simply returning pages to a free list can lead to external fragmentation over time, where the free pages become scattered across the memory address space, making it difficult to allocate large contiguous blocks for new sequences that require many pages. While paged KV cache inherently mitigates internal fragmentation, external fragmentation can still occur if the allocation pattern is irregular. To address this, advanced inference engines may employ background defragmentation routines. These routines periodically scan the memory layout and attempt to coalesce adjacent free pages into larger contiguous blocks, or they may use a buddy allocator strategy to manage memory blocks of varying sizes. Defragmentation is a computationally expensive operation that involves moving data within GPU memory, so it is typically performed during idle periods or when the fragmentation level exceeds a certain threshold. The goal is to maintain a memory layout that allows for efficient allocation of large page groups, ensuring that new sequences can be served without stalling the inference pipeline.

The storage format of the KV cache is another critical dimension of optimization, involving significant trade-offs between numerical accuracy and memory throughput
