In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate text autoregressively, they must retain the attention states of all previously generated tokens to compute the attention mechanism for the next token. In a naive implementation, this results in a linear growth of memory consumption proportional to the sequence length, quickly exhausting the finite high-bandwidth memory (HBM) available on a single GPU. To mitigate this, advanced inference engines such as vLLM employ a technique known as PagedAttention, which draws a direct analogy to the operating system’s virtual memory management. This approach decouples the logical view of the KV cache from its physical storage, allowing for non-contiguous memory allocation that drastically reduces fragmentation and enables efficient sharing of common prefixes among multiple concurrent requests.

The fundamental unit of storage in this system is the "page." Unlike traditional contiguous arrays, the KV cache is divided into fixed-size blocks, or pages, which are allocated dynamically as the sequence grows. The size of these pages is a crucial hyperparameter that dictates the granularity of memory management. Typically, a page might hold the key and value vectors for a specific number of tokens, such as 16 or 32 tokens, depending on the model’s hidden dimension and the precision of the storage. The choice of page group sizing involves a delicate balance. If pages are too small, the overhead of managing the page table—a data structure that maps logical page indices to physical memory addresses—becomes significant. This overhead manifests as increased latency in the attention kernel, as the GPU must perform indirect memory accesses to gather the scattered KV blocks. Conversely, if pages are too large, internal fragmentation occurs. When a sequence length does not perfectly align with the page size, the remaining space in the last allocated page is wasted. This "slack" can accumulate across thousands of concurrent requests, leading to substantial memory waste. Therefore, optimal page sizing is often determined empirically, balancing the cost of page table lookups against the cost of internal fragmentation, with a common heuristic being to align page sizes with the GPU’s memory transaction granularity to maximize bandwidth utilization.

The allocation strategy in a paged KV cache is designed to maximize memory utilization by allowing non-contiguous physical storage. When a new token is generated, the inference engine checks if the current logical page has space. If it does, the new KV pair is written into the existing physical page. If the page is full, a new physical page is allocated from the free pool, and the page table is updated to map the next logical index to this new physical location. This mechanism eliminates the need for contiguous memory blocks, which is a major source of fragmentation in traditional static allocation schemes. In a single-GPU environment, where memory is a scarce resource, this flexibility is paramount. It allows the engine to pack multiple sequences tightly together in memory, regardless of their individual lengths or growth rates. This is particularly beneficial in batched inference scenarios, where sequences of varying lengths are processed simultaneously. By avoiding the need to reserve large contiguous chunks for each sequence, the paged approach ensures that the GPU’s HBM is utilized to its maximum capacity, thereby increasing the effective batch size and overall throughput.

However, the dynamic nature of page allocation introduces the challenge of memory pressure and the need for eviction and defragmentation strategies. As the number of active sequences grows, the free pool of physical pages may deplete. When this happens, the inference engine must decide which pages to evict to make room for new allocations. The eviction policy is critical for maintaining system stability and performance. A common strategy is Least Recently Used (LRU) eviction, where the pages that have not been accessed for the longest time are discarded. In the context of LLM inference, this often translates to evicting the KV caches of sequences that have been idle for the longest duration or that have the lowest priority. More sophisticated engines may employ reference counting or priority-based eviction, where pages associated with high-priority or long-running tasks are protected from eviction. Defragmentation, in the strict sense of moving data to consolidate free space, is generally avoided in real-time inference engines due to the high cost of memory copying. Instead, the paged architecture inherently prevents external fragmentation by design. Internal fragmentation, however, remains a concern. To manage this, some engines implement a "compaction" step during idle periods, where they physically move KV data to consolidate free pages, reducing the number of scattered allocations. This process is computationally expensive and is therefore scheduled carefully, often during low-load periods, to minimize the impact on active inference latency.
