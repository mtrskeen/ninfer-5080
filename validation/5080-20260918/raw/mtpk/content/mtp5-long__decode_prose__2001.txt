In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As sequence lengths expand from hundreds to tens of thousands of tokens, the raw memory footprint of the KV cache can easily exceed the capacity of even high-end High-Bandwidth Memory (HBM) stacks, such as those found in NVIDIA A100 or H100 GPUs. Traditional contiguous memory allocation for KV tensors is inherently inefficient due to fragmentation and the dynamic nature of autoregressive generation. To address this, advanced inference frameworks like vLLM and TensorRT-LLM employ a paged KV cache strategy, which decouples logical token sequences from physical memory blocks, thereby enabling non-contiguous storage that mimics the virtual memory management techniques used in operating systems. This approach allows the inference engine to maximize GPU utilization by eliminating external fragmentation and allowing for fine-grained control over memory residency, which is essential when serving multiple concurrent requests with varying context lengths.

The fundamental unit of this system is the "page," a fixed-size block of memory that stores the key and value vectors for a specific number of tokens. In a standard transformer architecture, each token’s attention state consists of a key vector and a value vector, each with dimensions determined by the model’s hidden size and the number of attention heads. For instance, in a model with a hidden size of 4096 and 32 attention heads, the dimensionality of the KV state per token is significant. By grouping these vectors into pages, the inference engine abstracts the linear sequence of tokens into a list of page indices. The size of a page, often referred to as the page group size, is a hyperparameter that dictates the granularity of memory management. Typically, a page might store the KV data for 16 or 32 tokens. This sizing decision involves a delicate balance: if the page size is too small, the overhead of managing a large number of page table entries and pointer indirections increases, leading to higher latency in the attention kernel due to scattered memory access patterns. Conversely, if the page size is too large, internal fragmentation occurs when a sequence ends mid-page, wasting the remaining space in that block. Therefore, optimal page sizing is usually tuned based on the expected distribution of request lengths; shorter, chatty interactions benefit from smaller pages to minimize waste, while long-context document processing may tolerate larger pages to reduce metadata overhead.

When a new token is generated during the autoregressive phase, the inference engine must allocate space for its corresponding KV entry. If the current page associated with the active sequence has available slots, the new token’s KV data is written directly into that page. However, if the page is full, the engine must allocate a new physical page from the free pool and update the page table for that specific sequence to include the new page index. This dynamic allocation ensures that memory is only committed as needed, rather than pre-allocating the maximum possible context length for every request. This lazy allocation strategy is crucial for supporting high concurrency, as it allows the system to accept more concurrent requests than would be possible if each request reserved memory for its maximum potential length upfront. The page table acts as an indirection layer, mapping the logical token index to the physical page ID and the offset within that page. During the attention computation, the kernel does not read a contiguous buffer; instead, it iterates through the page table for the given sequence, gathering the relevant KV vectors from their respective physical locations. Modern attention kernels are optimized to handle this non-contiguous access pattern efficiently, often using coalesced memory reads within each page to maintain high bandwidth utilization on the HBM.

As the number of active sequences grows, the pool of free pages eventually depletes, triggering the need for eviction and defragmentation strategies. In a single-GPU environment, there is no offloading to CPU RAM or secondary storage, so memory pressure must be resolved internally. Eviction policies determine which sequences or partial sequences are discarded to free up pages for new incoming requests. Common strategies include Least Recently Used (LRU), which evicts the oldest inactive sequences, or priority-based eviction, where lower-priority requests are sacrificed to preserve high-priority or long-running tasks. More sophisticated systems may implement preemption, where the KV cache of a running sequence is saved to a temporary buffer or serialized, the pages are freed, and the sequence is re-scheduled later when memory becomes available. This re-scheduling involves reconstructing the KV state from the saved buffer, which incurs a computational cost but prevents the complete failure of the request. Defragmentation, on the other hand, is a background process that attempts to consolidate fragmented free pages into larger contiguous blocks, although in a strictly paged system, true defragmentation is less necessary than in contiguous allocation schemes because the page table handles the discontiguity.
