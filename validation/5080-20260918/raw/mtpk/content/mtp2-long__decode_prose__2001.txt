In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As LLMs scale to billions of parameters, the autoregressive nature of token generation necessitates storing the intermediate states of all previously generated tokens to avoid redundant computation in subsequent attention layers. In a naive implementation, this results in a monolithic, contiguous block of memory allocated for the KV cache per sequence. However, as concurrent batch sizes increase to maximize GPU utilization, this contiguous allocation strategy leads to severe external fragmentation and significant memory waste, particularly when sequences of varying lengths are processed simultaneously. Paged KV cache, a concept borrowed from virtual memory management in operating systems, resolves these issues by decoupling logical address space from physical memory layout. This technique allows the inference engine to manage KV cache memory in fixed-size blocks, or "pages," which can be allocated and freed dynamically, thereby minimizing fragmentation and enabling efficient sharing of common prefixes among multiple sequences.

The fundamental mechanism of a paged KV cache begins with the definition of the page size, which is determined by the product of the number of layers in the transformer model, the number of key-value heads per layer, the head dimension, and the page group size. The page group size is a crucial hyperparameter that dictates how many tokens are stored within a single physical page. Typically, this value is set to a small integer, such as 16 or 32 tokens, to balance granularity against metadata overhead. If the page size were too small, the overhead of managing the page table—essentially a mapping between logical token positions and physical memory indices—would become prohibitive relative to the actual data stored. Conversely, if the page size were too large, the last page of a sequence would likely contain significant wasted space, known as internal fragmentation, especially if the sequence length is not a perfect multiple of the page size. By standardizing the page size, the inference engine can treat the entire GPU memory pool as a uniform array of pages. Each active sequence maintains a logical view of its KV cache, where token index $i$ maps to a specific page index $p$ and an offset within that page. This indirection layer is managed via a page table, which is itself a small tensor residing in GPU memory, allowing the attention kernels to gather the correct physical memory locations for each token during the forward pass.

Page allocation occurs dynamically as new tokens are generated. When a sequence requires additional capacity for its KV cache, the inference engine checks the global free list of available pages. If sufficient contiguous logical space is required for the next token but no single free page has enough remaining slots, the engine allocates a new physical page from the free pool and updates the sequence’s page table to point to it. This process ensures that memory is only consumed as needed, rather than pre-allocating the maximum possible context length for every sequence, which would quickly exhaust GPU memory in high-concurrency scenarios. The efficiency of this allocation strategy is further enhanced by the ability to share pages among multiple sequences. In scenarios where multiple users request completions based on the same system prompt or few-shot examples, the inference engine can identify the common prefix and allocate a set of shared pages for those initial tokens. These shared pages are marked as read-only and referenced by the page tables of all sequences that share the prefix. This feature, often referred to as prompt caching or multi-shot caching, drastically reduces memory footprint and improves time-to-first-token (TTFT) latency, as the computation for the common prefix needs to be performed only once.

Eviction and defragmentation strategies are essential for maintaining long-term stability in the inference engine, particularly under sustained load. Unlike traditional memory managers, the paged KV cache does not require contiguous physical memory for logical contiguity, which inherently mitigates external fragmentation. However, the page table itself must be kept compact and efficient. When a sequence completes or is preempted due to memory pressure, its associated pages are released back to the free pool. The engine employs a least-recently-used (LRU) or similar policy to determine which sequences to evict when the memory pool is full. Preemption involves temporarily offloading the KV cache of lower-priority sequences to CPU memory or swapping them out entirely, allowing higher-priority sequences to continue processing. Upon resumption, the pages are reallocated, and the page table is reconstructed. To handle the inherent internal fragmentation caused by partial page usage, some advanced implementations employ compaction techniques. During periods of low activity or at specific intervals, the engine may copy the valid data from partially filled pages into new, fully packed pages, thereby freeing up the fragmented pages for reuse. This defragmentation process is computationally expensive due to the data movement involved, so it is typically scheduled asynchronously or during idle cycles to avoid impacting the latency of active inference requests.
