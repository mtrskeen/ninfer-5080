In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As sequence lengths expand from hundreds to tens of thousands of tokens, the raw memory footprint of the KV cache can easily exceed the capacity of even high-end GPUs such as the NVIDIA H100 or A100, necessitating sophisticated memory management strategies that go far beyond simple contiguous allocation. The paged KV cache mechanism, popularized by systems like vLLM, addresses this challenge by borrowing concepts from virtual memory management in operating systems, treating the GPU’s High-Bandwidth Memory (HBM) not as a monolithic block but as a collection of fixed-size blocks, or "pages," that are allocated on demand. This approach fundamentally alters how the inference engine interacts with the hardware, decoupling logical token positions from physical memory addresses and enabling near-zero memory fragmentation while maximizing the utilization of available VRAM.

At the core of this system is the concept of page allocation, which operates on a granularity defined by the `block_size` parameter, typically ranging from 16 to 64 tokens per block. When a new user request arrives at the inference engine, the scheduler does not reserve a contiguous chunk of memory proportional to the maximum possible context length. Instead, it allocates blocks dynamically as the autoregressive generation process proceeds. For instance, if the `block_size` is set to 16, the engine maintains a global pool of free blocks. As the model generates tokens, the attention layer requires access to the keys and values of all preceding tokens to compute the self-attention scores. In a traditional contiguous implementation, appending a new token would require shifting the entire existing KV cache or pre-allocating a massive buffer, leading to significant waste if the actual generation length is shorter than the reserved space. In the paged architecture, however, the engine simply marks the next available block in the free list as "in-use" and maps the new token’s key-value vectors into that block. This allows multiple concurrent sequences to share the same physical memory pool without interfering with one another, provided they do not exceed their allocated block quotas. The mapping between logical token indices and physical block IDs is maintained in a lightweight metadata structure, often stored in CPU RAM or pinned GPU memory, allowing the GPU kernels to perform indirect memory accesses via pointer arithmetic. This indirection is crucial because it allows the inference engine to implement advanced scheduling policies, such as preemption, where low-priority sequences can have their blocks returned to the free pool temporarily to serve high-priority requests, only to be restored later when memory becomes available.

The sizing of these page groups is a delicate balancing act that directly influences both memory overhead and kernel execution efficiency. If the `block_size` is too small, such as 1 or 2 tokens, the metadata overhead becomes significant relative to the actual data stored, and the GPU’s memory controller may suffer from increased transaction latency due to a higher frequency of small, non-coalesced memory accesses. Conversely, if the `block_size` is too large, such as 512 tokens, the internal fragmentation within each block increases substantially. Internal fragmentation occurs when a sequence terminates before filling its current active block, leaving unused slots in that block that cannot be utilized by other sequences until the block is fully freed. For example, with a `block_size` of 64, if a sequence ends after 10 tokens in a newly allocated block, 54 slots are wasted. Therefore, optimal `block_size` selection depends on the expected distribution of output lengths in the workload. In workloads with highly variable output lengths, smaller blocks reduce internal fragmentation but increase metadata pressure, whereas in workloads with consistent, long-form generations, larger blocks improve memory access coalescing and reduce the number of pointer indirections required by the attention kernels. Modern inference engines often expose this parameter for tuning, allowing operators to adjust the trade-off based on specific hardware characteristics and application requirements. Furthermore, the physical layout of these pages within the HBM is critical; the engine must ensure that pages belonging to the same sequence are distributed in a manner that minimizes bank conflicts and maximizes bandwidth utilization during the bulk reads performed by the FlashAttention or similar fused kernels.

Eviction and defragmentation strategies in a paged KV cache system are inherently different from those in traditional memory managers. Since the cache is divided into discrete blocks, "defragmentation" is largely obviated by the paging mechanism itself; there is no need to physically move data to create contiguous free spaces because any free block can be allocated to any sequence regardless of its position in the memory address space. However, eviction remains a critical component for managing memory pressure. When the free block pool is exhausted and a new high-priority request arrives, the scheduler must identify existing sequences to preempt.
