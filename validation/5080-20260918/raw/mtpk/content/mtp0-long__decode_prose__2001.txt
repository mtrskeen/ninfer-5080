In the realm of high-performance Large Language Model (LLM) inference, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As models scale to billions of parameters, the autoregressive nature of token generation necessitates that the attention mechanism retains all previously computed key and value vectors for every active sequence. Without an efficient storage strategy, the memory footprint of the KV cache grows linearly with the sequence length, quickly exhausting the limited High-Bandwidth Memory (HBM) available on a single GPU. This constraint is particularly acute in single-GPU inference engines, where there is no opportunity to shard the cache across multiple devices or nodes to distribute the memory load. Consequently, modern inference frameworks have moved away from simple contiguous array allocations toward sophisticated paged memory management systems, often inspired by operating system virtual memory concepts. The core idea behind a paged KV cache is to decouple logical sequence length from physical memory allocation, allowing the system to manage memory in fixed-size blocks known as pages, thereby eliminating external fragmentation and enabling more flexible, dynamic memory utilization.

The fundamental unit of this architecture is the "page," which serves as the atomic block of physical memory allocated for KV data. In a typical implementation, such as those found in vLLM or similar optimized runtimes, a page might consist of a fixed number of tokens, for example, 16 tokens. Each page stores the key and value tensors for those specific tokens across all attention heads and layers of the transformer model. When a new sequence begins, or when an existing sequence generates new tokens, the inference engine does not allocate a massive contiguous chunk of memory proportional to the total potential sequence length. Instead, it allocates individual pages as needed. If a sequence requires 100 tokens, the engine will allocate approximately six or seven pages (depending on the page size), leaving the unused portion of the last page as internal fragmentation. This approach ensures that the physical memory layout remains dense and manageable. The logical-to-physical mapping is maintained via a block table, which maps each logical token index to a specific physical page ID and an offset within that page. This indirection layer is crucial because it allows the attention kernels to gather data from non-contiguous physical locations without requiring the underlying memory to be contiguous in HBM. The attention computation itself is adapted to handle this fragmented layout; instead of performing a standard matrix multiplication over a contiguous tensor, the kernel iterates over the block table, fetching the relevant slices of keys and values from their respective physical pages and concatenating them virtually for the dot product operations. While this introduces some overhead due to indirect memory access patterns, the benefit of avoiding external fragmentation and enabling preemption far outweighs the cost, especially given the high bandwidth of modern HBM.

Page group sizing is a hyperparameter that directly influences both memory efficiency and computational performance. The size of a page determines the granularity of memory allocation. A smaller page size, such as 1 token per page, minimizes internal fragmentation, ensuring that almost no memory is wasted on partially filled pages. However, this comes at the cost of increased metadata overhead, as the block table must store an entry for every single token, leading to a larger control structure that consumes valuable L1/L2 cache space on the GPU. Furthermore, frequent small allocations can lead to higher latency in the memory allocator’s bookkeeping routines. Conversely, a larger page size, such as 32 or 64 tokens per page, reduces the frequency of allocation events and shrinks the size of the block table, improving cache locality for the metadata. However, this increases internal fragmentation. If a sequence ends abruptly between page boundaries, the remainder of the allocated page is wasted until the next sequence can utilize it. In a single-GPU environment, where memory is the primary constraint, finding the optimal page size involves balancing these two forces. Typically, a page size of 16 tokens strikes a reasonable balance, providing sufficient granularity to keep internal fragmentation low while maintaining a manageable block table size. Some advanced systems implement variable page sizes or hierarchical paging, where smaller pages are grouped into larger super-pages for bulk operations, further optimizing the trade-off between flexibility and efficiency.

Eviction and defragmentation are essential mechanisms for maintaining system stability under heavy load. In a single-GPU inference server, the total number of concurrent sequences that can be served is limited by the available HBM capacity for the KV cache. When the memory pool becomes full, the engine must decide which sequences to evict to make room for new incoming requests. This process is governed by a scheduling policy, often based on priority, age, or expected completion time. Unlike traditional operating systems that may swap pages to slower secondary storage, a single-GPU inference engine typically cannot afford the latency of moving KV data to CPU RAM or NVMe storage, as this would stall the attention computation for the remaining active sequences.
