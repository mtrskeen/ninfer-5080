In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As sequence lengths expand from hundreds to tens of thousands of tokens, the raw memory footprint of the KV cache can easily exceed the capacity of even high-end GPUs such as the NVIDIA H100 or A100, necessitating sophisticated memory management strategies that go far beyond simple contiguous allocation. The concept of a paged KV cache, popularized by systems like vLLM, addresses this by borrowing principles from virtual memory management in operating systems, treating the GPU’s High Bandwidth Memory (HBM) not as a monolithic block but as a collection of fixed-size blocks, or "pages," that are allocated on demand. This approach fundamentally alters how the inference engine interacts with the GPU memory hierarchy, decoupling logical sequence length from physical memory layout and enabling dynamic, fine-grained resource utilization that maximizes batch size while minimizing memory fragmentation.

The core mechanism of page allocation in a paged KV cache system involves mapping the logical keys and values generated during the autoregressive decoding process into discrete physical slots within the GPU memory. Unlike traditional continuous caching methods where each new token requires extending a contiguous array—leading to significant memory waste due to alignment constraints and fragmentation—a paged system divides the total KV cache space into uniform chunks. For instance, if the total available VRAM for KV storage is 24 GB and the page size is set to 16 KB, the system creates a table of 1,536,000 potential pages. Each active sequence in the inference batch is assigned a list of these page indices. When a new token is generated, the inference engine does not copy data; instead, it simply updates the pointer table to indicate that the next physical page contains the newly computed key and value vectors for that specific token. This indirection allows the physical locations of the KV tensors for a given sequence to be non-contiguous in memory. The attention kernel, which is the primary consumer of this data, must therefore be modified to accept these scattered pointers rather than assuming a linear memory address space. Modern CUDA kernels utilize gather operations or specialized index-based access patterns to fetch the relevant key and value vectors from their disparate physical locations, performing the necessary dot products and softmax calculations without requiring the data to be physically adjacent. This design enables the inference engine to pack multiple sequences into the available memory with near-zero internal fragmentation, as any unused "holes" in the memory map can be utilized by other concurrent sequences.

Determining the optimal page group sizing is a nuanced engineering decision that balances overhead against granularity. The page size effectively dictates the resolution of memory allocation. If the page size is too small, such as 1 KB, the overhead associated with maintaining the page table becomes significant. For a long context window of 32,768 tokens, a 1 KB page size would require 32,768 entries in the page table per sequence, per layer. In a transformer model with 80 layers, this results in millions of metadata entries that consume valuable register file and L1 cache space, potentially evicting actual model weights or activation data from fast caches. Conversely, if the page size is too large, such as 1 MB, the external fragmentation increases. A sequence that requires only slightly more than one page will still consume an entire megabyte, wasting up to nearly 1 MB of VRAM per layer. In practice, inference engines typically select page sizes that align with the hardware’s memory transaction boundaries, often ranging from 16 KB to 64 KB. This size is chosen to ensure that the number of pages required for a typical sequence remains manageable (e.g., a few thousand entries), keeping the page table compact enough to fit in the GPU’s L2 cache or shared memory, thereby reducing the latency associated with looking up physical addresses during the attention computation. Furthermore, the page size must be compatible with the quantization format of the stored data; for example, if using INT4 quantization, the effective byte count per token is halved compared to FP16, which may allow for smaller logical page sizes to maintain similar granularity without increasing the page table size disproportionately.

Eviction and defragmentation policies are essential for maintaining long-term stability and preventing out-of-memory errors in high-concurrency scenarios. In a paged system, eviction is not about deleting data from the GPU but rather reclaiming page slots for reuse. When a sequence completes generation or is preempted due to memory pressure, its associated page indices are returned to a free-list pool. However, because pages are allocated dynamically, the free space can become fragmented over time. While the paged nature inherently mitigates external fragmentation by allowing any free page to be used by any sequence, internal fragmentation can still occur if sequences have varying lengths that do not align perfectly with page boundaries.
