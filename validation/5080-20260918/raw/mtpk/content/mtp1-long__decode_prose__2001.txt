In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the current output. Without a persistent storage strategy, the computational cost would scale quadratically with sequence length, rendering long-context generation infeasible. The PagedAttention mechanism, introduced by vLLM and adopted by subsequent frameworks like SGLang and TensorRT-LLM, solves this by treating the KV cache not as a contiguous block of memory, but as a collection of fixed-size blocks, or "pages," managed by a dedicated allocator. This approach mirrors the operating system’s virtual memory paging, allowing for non-contiguous physical memory allocation while maintaining logical continuity for the attention kernel. The fundamental unit of this system is the page, which typically stores the key and value tensors for a specific number of tokens, known as the block size. In a standard implementation, this block size might be set to 16 or 32 tokens, striking a balance between metadata overhead and memory fragmentation. Each page is allocated from a pre-allocated pool of GPU memory, ensuring that the total memory footprint is bounded and predictable, unlike dynamic allocation strategies that can lead to unpredictable memory spikes or out-of-memory errors during peak concurrency.

The process of page allocation begins when a new request enters the inference engine. Upon initialization, the system allocates a small number of pages to store the initial prompt embeddings and the first few generated tokens. As the autoregressive loop proceeds, generating one token at a time, the attention head computes new key and value vectors for the newly generated token. These vectors are appended to the existing KV cache. If the current page is full—meaning it has reached its capacity of 16 or 32 tokens—the allocator must immediately provision a new page from the free list. This operation is extremely lightweight compared to traditional dynamic memory allocation because it involves simple pointer manipulation and table lookups rather than complex heap management or memory copying. The logical view of the KV cache is maintained through a block table, which maps logical block indices to physical page addresses. This indirection layer is crucial; it allows the attention kernel to gather data from scattered physical locations without requiring the underlying memory to be contiguous. The attention kernel itself is modified to accept this block table as an input parameter. Instead of performing a single large matrix multiplication on a contiguous tensor, the kernel iterates over the logical blocks, fetching the corresponding physical pages and computing partial attention scores for each block. These partial results are then reduced to produce the final attention output. This gather-scatter pattern introduces some additional overhead in terms of memory bandwidth transactions, as the GPU must perform multiple smaller reads rather than one large vectorized read. However, this overhead is significantly outweighed by the benefits of memory compaction and the ability to share pages across concurrent requests.

Page sharing is a key feature enabled by this paged architecture, particularly in scenarios involving multi-turn conversations or prefix caching. When multiple user requests share a common prompt prefix, such as a system instruction or a long document context, the inference engine can map the logical blocks of these shared prefixes to the same physical pages. This drastically reduces the memory footprint and the time spent recomputing the KV states for the shared portion. The block table for each request will reference the same physical pages for the prefix region, but diverge into unique pages once the user-specific content begins. This sharing mechanism is managed by a reference count on each physical page. A page remains allocated as long as at least one active request references it. When the last request referencing a particular page completes, the reference count drops to zero, and the page is returned to the free pool for reuse. This reference-counting scheme ensures safety without requiring complex garbage collection cycles, making it suitable for real-time inference environments where latency is paramount.

Eviction and defragmentation strategies become necessary when the demand for KV cache exceeds the available GPU memory. In a single-GPU setup, there is no option to offload to CPU RAM or NVMe storage without incurring significant latency penalties, so the engine must prioritize which active requests to keep in memory. Most modern engines implement a Least Recently Used (LRU) or priority-based eviction policy. When the free pool is exhausted and a new page is required for an active request, the engine selects a victim request based on its priority or recency. The entire KV cache of the victim request is evicted, and all pages associated with it are released back to the free pool. While this prevents out-of-memory crashes, it results in the loss of computation for the evicted request, which must be reprocessed if it is ever resumed. To mitigate the performance impact of frequent evictions, engines often employ preemption strategies that pause lower-priority requests before they are fully evicted, allowing them to resume quickly if higher-priority traffic subsides
