In the landscape of modern large language model (LLM) inference, the Key-Value (KV) cache represents the primary bottleneck for memory bandwidth and capacity. As models scale to billions of parameters, the sheer volume of hidden states required to maintain context grows linearly with sequence length, quickly exhausting the high-bandwidth memory (HBM) available on a single GPU. To mitigate this, advanced inference engines have moved away from contiguous memory allocation for the KV cache in favor of a paged KV cache architecture, inspired by virtual memory management in operating systems. This mechanism decouples logical address space from physical memory layout, allowing the inference engine to manage non-contiguous blocks of memory efficiently. The core concept revolves around dividing the KV cache into fixed-size units known as "pages." Each page holds the key and value vectors for a specific number of tokens, typically defined by a parameter such as `page_size`. For instance, if a model has a hidden dimension of 4096 and uses a page size of 16, each page stores 16 token’s worth of key and value tensors. This granularity is critical because it allows the system to allocate memory only when necessary, rather than reserving a massive contiguous block for the maximum possible sequence length upfront. In a single-GPU environment, this approach eliminates the fragmentation issues inherent in traditional static allocation schemes, where varying sequence lengths lead to significant wasted memory due to alignment constraints or power-of-two rounding up.

The process of page allocation begins at the start of an inference request. When a new prompt arrives, the inference engine initializes a logical table that maps logical page indices to physical page indices. Initially, no physical pages are allocated. As the autoregressive generation proceeds, the engine processes the input sequence in chunks. If the current logical page index does not yet have a corresponding physical page, the allocator searches the free list of physical pages to find an available slot. This search is optimized using data structures like bitmaps or linked lists to ensure O(1) or near-O(1) lookup times, which is crucial given that allocation decisions must happen every step of the generation loop. Once a physical page is selected, its index is recorded in the logical-to-physical mapping table. This indirection layer is the heart of the paged KV cache; it allows the attention kernel to gather keys and values from disparate physical locations without requiring them to be contiguous in HBM. The attention computation itself must be adapted to handle this non-contiguity. Standard fused attention kernels assume contiguous memory access patterns to maximize memory coalescing and hardware utilization. However, with paged KV caches, the kernel must perform indirect memory accesses. Modern CUDA implementations achieve this by using vectorized loads that fetch data from multiple physical pages in parallel, leveraging the GPU’s ability to hide latency through instruction-level parallelism. While this introduces a slight overhead compared to perfectly contiguous access, the savings in memory capacity far outweigh the minor throughput penalty, especially for long-context workloads where contiguous allocation would simply fail due to out-of-memory errors.

Page group sizing is a critical hyperparameter that balances memory efficiency against access granularity. A smaller page size, such as 1 or 2 tokens per page, offers finer-grained control over memory usage, reducing internal fragmentation—the waste of space within the last partially filled page of a sequence. However, smaller pages increase the overhead associated with managing the logical-to-physical mapping table and can lead to more frequent allocation events, potentially stressing the CPU-side allocator if not carefully managed. Conversely, larger page sizes, such as 16 or 32 tokens, reduce the frequency of allocation calls and simplify the metadata structure, but they introduce higher internal fragmentation. If a sequence ends mid-page, the remaining slots in that page are wasted until the page is freed. Therefore, optimal page group sizing is workload-dependent. For short, bursty queries, smaller pages may be preferable to minimize waste, while for long, steady-state generations, larger pages can improve allocator throughput and reduce metadata bloat. Furthermore, the choice of page size interacts with the quantization format of the KV cache. Since quantized formats reduce the byte count per element, the effective "logical" size of a page in terms of memory footprint changes, necessitating a re-evaluation of the optimal page size to maintain consistent memory pressure levels across different precision modes.

Eviction and defragmentation strategies become essential when the pool of free physical pages is exhausted. In a single-GPU setup, there is no secondary storage tier like CPU RAM to spill to immediately; instead, the engine must prioritize which active sequences to keep resident in HBM. Eviction policies typically follow a Least Recently Used (LRU) heuristic or a priority-based scheme where interactive user requests are prioritized over batch jobs. When a new request arrives and no free pages exist, the engine identifies the least valuable active sequence and frees its associated physical pages back to the pool. This immediate freeing allows the new request to proceed, ensuring low latency for incoming traffic. However, aggressive eviction can lead to thrashing if the working set of active sequences exceeds the total available memory. To counteract this, sophisticated engines implement preemption mechanisms that swap out less critical sequences to a slower memory tier (if available via unified memory architectures) or terminate them entirely, depending on the service level agreement. Defragmentation, in the context of paged KV caches, is largely obviated by the design itself. Since the logical-to-physical mapping allows for non-contiguous physical layouts, the engine never needs to move data in memory to consolidate free space. This is a profound advantage over traditional heap allocators, which suffer from external fragmentation that degrades performance over time. The paged approach effectively treats the GPU HBM as a segmented file system, where "files" (sequences) can reside anywhere, and the directory structure (mapping table) keeps track of their locations. This eliminates the need for costly compaction operations that would stall inference during runtime, thereby maintaining consistent throughput even under heavy load.

The trade-offs between FP16, INT8, and INT4 quantized KV storage represent a complex optimization surface involving accuracy, memory capacity, and computational throughput. FP16 (16-bit floating point) serves as the baseline, offering the highest numerical fidelity for key and value tensors. It preserves the full dynamic range and precision required for accurate attention score calculations, minimizing the risk of information loss during the dot product operations. However, FP16 storage consumes the most memory, limiting the maximum context length and the number of concurrent sequences that can be served. For many production LLMs, FP16 KV caches quickly exhaust VRAM, forcing early truncation of context or limiting batch sizes. INT8 quantization reduces the memory footprint by half compared to FP16, allowing for twice the context length or double the concurrency. The accuracy impact of INT8 is generally minimal for most tasks, as the reduced precision is sufficient to capture the relative magnitudes of attention weights. However, it requires careful calibration to determine the scaling factors that map the FP16 range to the INT8 range. Poor calibration can lead to clipping artifacts, where extreme values are lost, degrading model performance on edge-case inputs. From a throughput perspective, INT8 KV storage often results in improved effective memory bandwidth utilization. Since fewer bytes need to be transferred from HBM to the compute units for each attention operation, the memory-bound nature of LLM inference is alleviated. Many modern GPUs feature specialized tensor cores that support mixed-precision operations, allowing the attention computation to be performed in lower precision while accumulating results in higher precision, further boosting speed.

INT4 quantization takes this compression further, reducing the memory footprint to one-quarter of FP16. This drastic reduction enables serving extremely long contexts or massive batch sizes that would be impossible with FP16 or even INT8. The accuracy trade-off here is more significant. Quantizing to 4 bits introduces substantial quantization noise, which can degrade the quality of generated text, particularly in tasks requiring fine-grained semantic distinctions. To mitigate this, state-of-the-art engines employ advanced techniques such as Group-wise Quantization, where the KV cache is divided into small groups (e.g., 128 elements), and each group has its own scale and zero-point. This local normalization helps preserve the relative distribution within each group, significantly improving accuracy over naive per-tensor quantization. Additionally, some engines use hybrid approaches, keeping the most recent tokens in higher precision (FP16 or INT8) while storing older, less critical history in INT4. This exploits the recency bias in attention mechanisms, where recent tokens contribute more significantly to the next prediction. Throughput benefits with INT4 are substantial, primarily driven by the reduced memory bandwidth requirements. The attention kernel becomes less bound by data movement and more bound by compute, allowing the GPU to operate closer to its peak FLOPS capability. However, the conversion overhead between formats (if mixed precision is used) and the complexity of dequantization logic can introduce latency spikes if not carefully optimized.

In conclusion, the paged KV cache architecture transforms LLM inference from a memory-constrained task into a manageable resource allocation problem. By abstracting physical memory into logical pages, engines can dynamically adapt to varying sequence lengths, eliminate fragmentation, and maximize hardware utilization. The interplay between page sizing, eviction policies, and quantization formats creates a multi-dimensional optimization space. FP16 provides the gold standard for accuracy but suffers from capacity limits; INT8 offers a balanced compromise with modest accuracy gains in throughput; and INT4 pushes the boundaries of what is possible in terms of context length and concurrency, albeit with increased complexity in maintaining output quality. For a single-GPU inference engine, mastering these components is essential to delivering high-throughput, low-latency services. The continuous refinement of these techniques—such as adaptive page sizing based on real-time load metrics, smarter eviction heuristics that predict future demand, and error-corrected quantization schemes—will continue to drive the evolution of LLM deployment, enabling ever-larger models to run efficiently on increasingly powerful, yet finite, GPU resources. The synergy between memory management and numerical precision ensures that the theoretical capabilities of large language models can be realized in practical, scalable infrastructure.
