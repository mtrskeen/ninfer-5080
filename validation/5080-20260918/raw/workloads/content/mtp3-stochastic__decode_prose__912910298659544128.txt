In the architecture of modern large language model (LLM) inference engines, particularly those deployed on single-GPU systems, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As autoregressive transformers generate tokens sequentially, the attention mechanism requires access to all previously generated keys and values to compute the current token’s context. In a naive implementation, this results in a linearly growing tensor that consumes vast amounts of GPU High-Bandwidth Memory (HBM). Paged KV caching, inspired by the operating system concept of virtual memory paging, decouples logical address space from physical memory allocation, allowing for dynamic, fine-grained management of these tensors. This mechanism is not merely an optimization but a fundamental shift in how state is stored, enabling high-concurrency serving with significantly reduced memory fragmentation compared to contiguous buffer allocations.

The core principle of paged KV caching involves dividing the KV cache into fixed-size blocks, often referred to as "pages." Unlike traditional memory allocation where a request might be assigned a large, contiguous chunk of memory proportional to its maximum potential length, paged caching allocates memory only as needed. Each page contains a specific number of key-value pairs, determined by the "page group sizing" parameter. This sizing is a critical hyperparameter that balances metadata overhead against memory utilization efficiency. If pages are too small, the engine must maintain a massive table of pointers to track the location of every individual token’s data, leading to significant CPU-side overhead and increased instruction fetch latency during the attention kernel execution. Conversely, if pages are too large, the last page of a sequence may remain partially filled, resulting in internal fragmentation where allocated memory is wasted because it cannot be shared with other requests. In practice, optimal page sizes typically range between 16 and 64 tokens per page, striking a balance that minimizes the ratio of wasted memory to pointer lookup cost. The physical layout of these pages is managed via a block table, which maps logical token indices to physical page IDs. This indirection layer allows the GPU kernels to gather non-contiguous memory segments efficiently using vectorized loads, ensuring that the hardware’s memory subsystem remains saturated despite the fragmented physical layout.

Page allocation in a single-GPU environment is governed by a strict demand-driven strategy. When a new inference request arrives, the engine does not pre-allocate memory for the entire predicted output length. Instead, it initializes the request with a minimal set of pages, usually just enough to hold the prompt’s encoded keys and values or a small initial buffer. As the model generates subsequent tokens, the attention computation produces new key and value vectors. These new vectors are appended to the existing KV cache. Once the current active page becomes full, the allocator triggers the creation of a new page. This process is atomic from the perspective of the GPU kernel; the kernel writes the new KV pair into the next available slot in the page table, and if that slot marks the end of a page, the allocator atomically assigns a new physical page ID to the logical index. This lazy allocation ensures that memory consumption scales strictly with actual generation length rather than worst-case scenarios, allowing the engine to serve many more concurrent users than would be possible with static reservation. Furthermore, in multi-turn conversations or streaming interfaces, the paged structure allows for efficient prefix sharing. If multiple users share a common system prompt, their initial KV pages can point to the same physical memory blocks, drastically reducing the memory footprint for the shared portion of the context.

However, the dynamic nature of page allocation introduces the challenge of memory fragmentation over time. As sequences complete and their associated pages are freed, the pool of available physical pages becomes scattered across the HBM. While this does not cause immediate failure due to the indirect addressing scheme, it can lead to performance degradation if the allocator fails to coalesce free pages efficiently. Defragmentation in a paged KV system is rarely performed via explicit moving of data, which would incur prohibitive copy costs on the GPU. Instead, modern engines employ sophisticated compaction strategies at the logical level. When a sequence is evicted or completed, its logical pages are marked as free in the block table. Advanced allocators utilize a "best-fit" or "first-fit" policy to assign new pages, attempting to pack allocations tightly to minimize the number of distinct physical regions in use. Some engines implement background defragmentation threads that run on the CPU, analyzing the block table and re-mapping logical indices to consolidate free space, provided that no active GPU kernel is currently reading those specific addresses. This re-mapping is purely a metadata operation, making it cheap and safe, effectively cleaning up the logical view of memory without touching the actual data in HBM. This approach ensures that long-running inference servers do not suffer from cumulative fragmentation that would eventually prevent new allocations, even if the total free memory appears sufficient.

The storage precision of the KV cache offers another dimension of optimization, involving trade-offs between numerical accuracy and memory bandwidth/throughput. By default, LLMs operate in FP16 (or BF16), storing keys and values with 16-bit precision. This provides high fidelity for the attention scores, ensuring that the softmax normalization and subsequent weighted sum of values are numerically stable. However, FP16 storage doubles the memory bandwidth requirements compared to lower-precision formats. Since the attention mechanism is memory-bound—relying heavily on loading K and V matrices from HBM into SRAM/registers—reducing the bit-width of the KV cache directly increases effective throughput. INT8 quantization reduces the storage size by half relative to FP16. In this regime, keys and values are quantized to 8-bit integers, typically using per-channel or per-tensor scaling factors to preserve the dynamic range. The dequantization step occurs on-the-fly within the attention kernel, adding a minor arithmetic overhead. Empirical studies show that INT8 KV caching often yields negligible loss in perplexity or downstream task accuracy for most open-source models, while providing a substantial boost in tokens-per-second throughput due to halved memory traffic. This makes INT8 the preferred choice for production-grade inference engines where moderate accuracy loss is acceptable in exchange for significant capacity and speed gains.

Pushing further into the compression spectrum, INT4 quantization halves the memory footprint again, offering a four-fold reduction compared to FP16. This is crucial for fitting larger context windows or higher concurrency levels on memory-constrained GPUs. However, INT4 is far more sensitive to quantization error. The limited dynamic range of 4 bits means that subtle variations in key values, which are essential for precise attention weight distribution, can be lost. To mitigate this, advanced schemes like KV-cache-aware quantization are employed, where the quantization grid is optimized specifically for the distribution of key/value tensors, which often exhibit different statistical properties than weight matrices. Some engines adopt mixed-precision strategies, such as storing keys in INT8 and values in INT4, or vice versa, depending on which component contributes more to the final attention output variance. For instance, since the value matrix undergoes a weighted summation, errors in values accumulate linearly, potentially causing greater drift than errors in keys, which influence the probability weights. Therefore, maintaining higher precision for values is often prioritized. Despite these optimizations, INT4 KV caching carries a risk of noticeable quality degradation, particularly in long-context scenarios where small errors compound over hundreds of steps. Consequently, while INT4 enables extreme scalability, it is generally reserved for batch-heavy workloads or smaller models where the baseline accuracy margin is sufficient to absorb the quantization noise.

The interaction between paged allocation and quantization creates a complex engineering landscape. The page size must be compatible with the vectorization capabilities of the GPU’s tensor cores or CUDA cores when handling quantized data. For example, if using INT8, the memory access patterns must align with 32-byte or 128-byte transaction boundaries to maximize bus utilization. A page size that is not a multiple of the alignment requirement will result in unaligned memory accesses, triggering penalties that negate the bandwidth savings of quantization. Therefore, the choice of page group sizing is not independent of the data format; it is tightly coupled with the hardware’s memory controller behavior. Furthermore, the eviction policy must account for the fact that quantized caches may require periodic recalibration or scale factor updates if the model’s output distribution shifts significantly during long generations. While rare, such drift can cause the fixed quantization parameters to become suboptimal, leading to gradual accuracy decay. Sophisticated engines monitor the variance of newly generated KV entries and may trigger a soft-defrag or re-quantization event if the statistical profile deviates beyond a threshold, ensuring that the compressed representation remains faithful to the model’s evolving state.

In summary, the paged KV cache in a single-GPU inference engine is a sophisticated hybrid of memory management and numerical approximation techniques. It solves the fragmentation problem inherent in variable-length sequence processing through logical-to-physical mapping, allowing for dense packing of diverse request lengths. Simultaneously, the integration of quantized storage formats leverages the memory-bound nature of attention to trade off some numerical precision for significant improvements in throughput and capacity. The synergy between fine-grained page allocation and aggressive quantization enables modern inference servers to handle thousands of concurrent streams with context lengths spanning tens of thousands of tokens, all within the constrained memory envelope of a single high-end GPU. This architectural evolution is central to the viability of LLMs in real-time applications, transforming what was once a prohibitively expensive memory problem into a manageable resource scheduling challenge.
