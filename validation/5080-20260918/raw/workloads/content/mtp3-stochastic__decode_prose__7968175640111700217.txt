The management of the Key-Value (KV) cache constitutes one of the most critical bottlenecks in modern Large Language Model (LLM) inference, particularly when deploying high-parameter models on a single GPU. As autoregressive decoding proceeds token by token, the attention mechanism requires access to all previously generated hidden states to compute the current output. In a naive implementation, this would result in linear memory growth proportional to the sequence length, quickly exhausting the finite capacity of High-Bandwidth Memory (HBM). To mitigate this, advanced inference engines employ a paged KV cache architecture, inspired by the operating system concept of virtual memory paging. This approach decouples logical sequence storage from physical memory allocation, allowing for efficient memory utilization, reduced fragmentation, and the ability to support multiple concurrent requests without pre-allocating maximum possible sequence lengths.

At the core of this architecture is the abstraction of the KV cache into fixed-size blocks known as "pages." Unlike traditional contiguous array allocations, where a new request might require a large, uninterrupted block of memory that may not be available due to fragmentation, a paged system allocates memory in small, uniform chunks. For instance, if a model has 32 layers, each with a key head dimension of 128 and a value head dimension of 128, using FP16 precision, the size of a single token’s KV data per layer is calculated as $2 \times 128 \times 2$ bytes (for both K and V) $\times 32$ layers, resulting in 16 KB per token. A page group, which serves as the atomic unit of allocation, might consist of 16 tokens. Therefore, a single page group occupies $16 \times 16 \text{ KB} = 256 \text{ KB}$ of GPU memory. By breaking the KV cache into these granular units, the inference engine can allocate memory dynamically based on actual usage rather than worst-case scenarios. When a new user request arrives, the engine does not reserve space for the potential maximum context window; instead, it allocates only the pages necessary for the initial prompt and subsequent generation steps. This lazy allocation strategy ensures that idle or short-lived conversations do not consume excessive memory resources, thereby maximizing the number of concurrent users the single GPU can serve.

The process of page allocation is tightly coupled with the attention computation kernel. During the forward pass of the transformer, the query vectors of the current token must attend to the key vectors stored in the previous pages. The attention kernel is designed to handle non-contiguous memory layouts efficiently. It iterates through the list of allocated page indices for the specific request, fetching the corresponding key and value tensors from their scattered physical locations in HBM. While this indirection introduces a slight overhead compared to contiguous memory access, the performance loss is negligible compared to the catastrophic failure modes of memory exhaustion or severe fragmentation seen in unpaged systems. Furthermore, the use of page groups allows for batched operations. If multiple requests share the same prefix (a common scenario in multi-turn chatbots or few-shot prompting), the engine can utilize copy-on-write semantics or shared page references. This means that the KV caches for the shared prefix are stored only once in physical memory, while the logical views for different requests point to the same set of physical pages. This deduplication significantly reduces memory footprint and improves throughput, especially in scenarios with high redundancy across sessions.

Eviction and defragmentation strategies become crucial as the system approaches its memory limits. In a paged system, defragmentation is largely an inherent benefit of the design. Since memory is allocated in discrete, uniform pages, there is no such thing as a "gap" between two active pages that cannot be utilized by another request. Any free page in the pool is immediately available for any new allocation, regardless of its location in the physical memory space. This eliminates the need for complex compaction algorithms that would otherwise pause inference to shift data around, a process that is prohibitively expensive on GPUs. However, eviction policies still govern what happens when the free page pool is exhausted. Most production-grade inference engines implement a Least Recently Used (LRU) or Least Frequently Used (LFU) policy at the request level. When a new request requires a page and none are free, the engine identifies the least valuable active request—typically one that has been idle for the longest duration or has the lowest priority—and evicts its entire KV cache. The physical pages occupied by this evicted request are returned to the global free pool. Importantly, because the pages are uniform, the released memory can be immediately reallocated to the waiting new request without any alignment issues or waste. Some advanced engines also implement preemptive eviction, where they monitor the memory pressure and begin evicting low-priority requests before the hard limit is reached, ensuring smooth latency for high-priority interactive users.

A significant aspect of optimizing single-GPU inference is the trade-off between numerical precision and memory bandwidth, which directly impacts both accuracy and throughput. The KV cache is read intensively during every step of the autoregressive generation, making it a primary consumer of HBM bandwidth. Storing the KV cache in standard FP16 (16-bit floating point) provides high numerical fidelity but consumes substantial memory. For a model like LLaMA-70B, the KV cache for a 4k-token context can exceed several gigabytes, potentially exceeding the VRAM of a single high-end GPU if multiple users are served. To address this, quantization techniques are applied to the KV cache. INT8 quantization scales the floating-point values to an 8-bit integer range, reducing the memory footprint by half compared to FP16. This reduction doubles the effective memory capacity, allowing for longer contexts or more concurrent users. The impact on accuracy is generally minimal for INT8, as the dynamic range of attention keys and values usually fits well within the 8-bit signed integer range, provided appropriate scaling factors are used per tensor or per head. Many state-of-the-art inference engines now default to INT8 KV caching, observing negligible degradation in perplexity or downstream task performance while achieving significant throughput gains due to improved memory efficiency and higher effective bandwidth utilization.

Going further, INT4 quantization reduces the memory footprint by a factor of four relative to FP16. This extreme compression is highly attractive for fitting massive models onto single GPUs with limited VRAM, such as an NVIDIA A100 40GB or H100 80GB. However, the accuracy trade-offs become more pronounced at this bit-width. Standard symmetric INT4 quantization often suffers from information loss, particularly in the tails of the distribution, which can lead to noticeable drops in generation quality, such as increased hallucination rates or grammatical errors. To mitigate this, sophisticated calibration techniques are employed. Methods like SmoothQuant or AWQ (Activation-aware Weight Quantization) analyze the activation distributions of the specific model to determine optimal clipping ranges and scaling factors. These methods recognize that not all channels in the KV tensor are equally sensitive to quantization error; some channels carry critical semantic information, while others contain noise. By applying finer-grained quantization (e.g., per-channel or per-head scaling) and potentially using asymmetric quantization to better capture the skewed distributions of attention values, engines can maintain acceptable accuracy even at 4 bits. Recent research suggests that with proper calibration, INT4 KV caches can achieve perplexities close to FP16 baselines for many tasks, though sensitive applications like code generation or strict factual retrieval may still exhibit higher error rates.

The choice between FP16, INT8, and INT4 is thus a strategic decision balancing hardware constraints against quality requirements. On a single GPU, the memory hierarchy is rigid; there is no offloading to CPU RAM that can absorb the overflow gracefully without introducing massive latency spikes due to PCIe bottleneck. Therefore, if the total KV cache size for the expected workload exceeds the available VRAM, the engine *must* reduce precision. An INT8 configuration offers the best balance, providing a 2x memory saving with near-lossless accuracy. An INT4 configuration is reserved for scenarios where the model is too large to fit in FP16/INT8 even with aggressive batching, or where the context lengths are extremely long (e.g., 32k+ tokens). In such cases, the throughput gain from halving the memory traffic (compared to INT8) or quartering it (compared to FP16) is essential to keep the Time-To-First-Token (TTFT) and inter-token latency within acceptable bounds. The attention kernel itself must be optimized to dequantize these integer values back to FP16 on-the-fly during the dot product computation. Modern CUDA kernels leverage Tensor Cores for mixed-precision matrix multiplications, performing the heavy lifting in lower precision and upcasting only the final accumulation, thereby preserving speed while managing the reduced precision storage.

In conclusion, the paged KV cache architecture transforms LLM inference from a memory-bound struggle into a manageable resource allocation problem. By abstracting memory into pages, the engine solves the fragmentation crisis inherent in variable-length sequence processing. The integration of quantized KV storage further extends the operational envelope of single-GPU deployments, allowing for the serving of larger models or denser user populations. The interplay between page allocation granularity, eviction policies, and quantization precision defines the performance profile of the inference engine. While FP16 remains the gold standard for accuracy, the practical realities of single-GPU memory limits make INT8 and, increasingly, calibrated INT4 the standard for production environments. The continuous refinement of these mechanisms—ensuring that page lookups are coalesced, that eviction is fair, and that quantization error is minimized through smart calibration—remains a central focus of LLM infrastructure development, enabling scalable, cost-effective, and high-quality language model services.
