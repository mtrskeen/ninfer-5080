In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the system divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory layout allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which stores the key and value vectors for a specific number of tokens. The sizing of these pages is a crucial design parameter that directly influences the trade-off between memory overhead and fragmentation. Typically, a page size is chosen to be a multiple of the number of attention heads and the head dimension, ensuring that the data layout is compatible with the GPU’s tensor core operations and memory coalescing requirements. For instance, if a model has 32 attention heads and a head dimension of 128, a page might store the KV data for 16 or 32 tokens. If the page size is too small, the metadata overhead associated with tracking the mapping between logical pages and physical pages becomes significant relative to the actual data stored, leading to increased memory pressure and slower index lookups. Conversely, if the page size is too large, the system suffers from external fragmentation, where the last page of a sequence may be only partially filled, wasting a substantial portion of the allocated memory. This "tail waste" is particularly problematic in scenarios with highly variable sequence lengths, such as in multi-turn chat applications where some conversations are short and others are long. Therefore, the optimal page size is often a balance that minimizes the total memory footprint while keeping the metadata management overhead within acceptable limits. In practice, many inference engines use a page size that corresponds to a small number of tokens, such as 16 or 32, which strikes a reasonable balance for most common model architectures and batch configurations.

The allocation strategy for these pages is managed by a central memory allocator that maintains a free list of available physical pages. When a new request arrives, the inference engine does not pre-allocate memory for the maximum possible sequence length. Instead, it allocates pages incrementally as the model generates new tokens. This on-demand allocation allows the system to serve a larger number of concurrent requests than would be possible with static allocation, as the memory for each request is only consumed as needed. The allocator must also handle the case where a request’s sequence length exceeds the available free pages. In such cases, the engine may need to preempt or swap out other requests to free up memory, a process that involves moving the KV cache of the preempted request to CPU memory or secondary storage. This preemption mechanism is essential for maintaining the stability of the inference engine under high load, ensuring that no single long-running request can starve other requests of memory resources. The allocator also needs to handle the deallocation of pages when a request completes, returning the physical pages to the free list for reuse by subsequent requests.

Eviction and defragmentation are critical components of the paged KV cache management strategy, particularly in long-running inference servers where memory fragmentation can accumulate over time. While the paged approach significantly reduces fragmentation compared to contiguous allocation, it is not immune to it. Over time, the free list may become fragmented, with many small blocks of free memory scattered throughout the address space, making it difficult to allocate large contiguous blocks of pages for new requests. To mitigate this, the inference engine can employ defragmentation techniques that consolidate free pages into larger contiguous blocks. This can be achieved through background compaction processes that run periodically or when the fragmentation level exceeds a certain threshold. During compaction, the engine may move the KV data of active requests to new physical pages, updating the logical-to-physical mapping tables to reflect the new locations. While this process incurs a temporary performance cost due to the memory copy operations, it ensures that the system remains efficient over the long term. Additionally, the engine can implement eviction policies that prioritize the removal of less frequently accessed or older KV pages to free up memory for new requests. These policies can be based on metrics such as the age of the request, the number of tokens generated, or the predicted future memory requirements of the request.
