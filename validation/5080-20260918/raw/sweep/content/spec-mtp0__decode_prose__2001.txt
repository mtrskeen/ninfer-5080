In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate text autoregressively, they must retain the attention keys and values for all previously generated tokens to compute the attention mechanism for the current token. In a naive implementation, this results in a massive, contiguous block of memory that grows linearly with the sequence length, leading to severe memory fragmentation and inefficient GPU memory utilization. Paged KV cache, a technique popularized by systems like vLLM, addresses these issues by borrowing concepts from virtual memory management in operating systems. Instead of allocating a single contiguous block for the entire sequence, the KV cache is divided into fixed-size blocks, or "pages," which are allocated on demand. This approach allows the inference engine to manage memory with the granularity of individual pages, significantly reducing internal fragmentation and enabling efficient sharing of KV cache blocks across multiple concurrent sequences, a feature known as copy-on-write.

The fundamental unit of this system is the page, which typically corresponds to a fixed number of tokens, often ranging from 16 to 64 tokens depending on the specific implementation and hardware constraints. The size of a page is a critical design parameter that directly influences the trade-off between memory overhead and management complexity. A smaller page size, such as 16 tokens, provides finer granularity, which minimizes the amount of wasted memory at the end of a sequence (internal fragmentation) and allows for more precise sharing of common prefixes in multi-user scenarios. However, smaller pages increase the metadata overhead required to track the mapping between logical sequence positions and physical memory pages. This metadata, stored in a block table, must be kept in CPU memory or fast GPU memory, and the frequent updates to this table during the decoding phase can introduce latency. Conversely, larger page sizes, such as 64 tokens, reduce the frequency of block table updates and lower the metadata overhead, but they increase the potential for internal fragmentation, especially for shorter sequences or when sequences terminate at arbitrary points. In a single-GPU environment, where memory bandwidth is a scarce resource, the choice of page size must be carefully calibrated to balance the cost of metadata management against the loss of effective memory capacity.

Page allocation in a paged KV cache system is managed by a dedicated memory allocator that maintains a free list of available physical pages. When a new token is generated for a sequence, the inference engine checks if the current logical page for that sequence has space for the new token. If the page is full, the allocator assigns a new physical page from the free list and updates the block table to map the next logical position to this new physical page. This process is analogous to page fault handling in an operating system, but it occurs proactively during the forward pass of the model. The key advantage of this mechanism is that it decouples the logical sequence length from the physical memory layout. This decoupling is essential for supporting variable-length sequences in a batch, as it allows the engine to pack multiple sequences into the available GPU memory without requiring them to be contiguous in physical space. Furthermore, this structure facilitates the implementation of copy-on-write (CoW) for prefix sharing. If multiple sequences share a common prefix, their block tables can point to the same physical pages for the shared portion. When a sequence diverges from the shared prefix, the inference engine copies the relevant physical pages to new, unique pages for that specific sequence, ensuring that subsequent writes do not corrupt the shared data. This CoW mechanism is particularly beneficial in scenarios involving system prompts or few-shot examples, where a large portion of the context is identical across many requests, thereby drastically reducing the total memory footprint.

Eviction and defragmentation are crucial aspects of maintaining the health of the paged KV cache, especially in long-running inference servers. Unlike traditional memory allocators that may suffer from external fragmentation over time, the paged KV cache system inherently mitigates external fragmentation by using fixed-size pages. However, internal fragmentation and the accumulation of "orphaned" pages can still occur if sequences are terminated abruptly or if the memory allocator does not efficiently reclaim pages. In a single-GPU setup, the inference engine must implement a robust eviction policy to handle memory pressure. When the GPU memory is nearing its limit, the engine must decide which sequences to evict. Common strategies include Least Recently Used (LRU) or priority-based eviction, where lower-priority or less-frequently accessed sequences are removed to free up pages. The eviction process involves invalidating the block table entries for the evicted sequence and returning the associated physical pages to the free list. To prevent performance degradation due to frequent evictions, the engine may also employ preemption techniques, such as swapping out the KV cache of a preempted sequence to CPU memory or disk, allowing it to be restored later if the sequence is resumed.
