In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously generated keys and values to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the system divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory layout allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which typically stores the key and value vectors for a fixed number of tokens, often referred to as the page size or block size. For instance, if the page size is set to 16 tokens, a single page holds the KV tensors for 16 consecutive tokens. The choice of page size is a critical design parameter that involves a delicate trade-off between memory overhead and management complexity. A smaller page size, such as 1 or 4 tokens, provides finer granularity, which minimizes the amount of wasted memory at the tail end of a sequence (internal fragmentation). However, this comes at the cost of increased metadata overhead, as the system must maintain a larger table of page pointers and perform more frequent memory allocation and deallocation operations. Conversely, a larger page size, such as 128 or 256 tokens, reduces the frequency of memory management operations and the size of the page table, thereby lowering CPU overhead and improving the efficiency of memory copy operations. However, larger pages increase the likelihood of internal fragmentation, where the last page of a sequence may be only partially filled, leading to wasted HBM capacity. In practice, inference engines often select a page size that balances these factors, typically ranging from 16 to 64 tokens, depending on the model’s hidden dimension and the expected sequence lengths. The physical memory for these pages is pre-allocated as a large, contiguous pool of GPU memory at initialization, ensuring that the GPU’s memory allocator is not constantly invoked during inference, which would introduce significant latency.

The allocation of these pages is managed by a sophisticated allocator that tracks the state of each page in the memory pool. When a new request arrives, the engine allocates pages for the prompt tokens and then dynamically allocates additional pages as the model generates new tokens during the decoding phase. This dynamic allocation is crucial for handling variable-length sequences efficiently. Unlike static allocation, where memory is reserved for the maximum possible sequence length, paged allocation allows the system to share memory resources among multiple concurrent requests. This is achieved through a mechanism known as copy-on-write or reference counting. If multiple requests share the same prefix (a common scenario in multi-turn conversations or few-shot prompting), the KV cache pages for that prefix can be shared across requests. The inference engine maintains a reference count for each page; as long as the count is greater than zero, the page remains in memory. When a request diverges from the shared prefix, the engine copies the necessary pages for the diverging request, a process that is optimized to minimize memory bandwidth usage. This sharing mechanism dramatically improves throughput by reducing the total amount of unique KV data that must be stored in HBM, allowing the engine to serve more concurrent requests within the same memory budget.

Eviction and defragmentation are essential components of the paged KV cache lifecycle, particularly in long-running inference servers where memory pressure can lead to out-of-memory (OOM) errors. Since the physical memory pool is fixed in size, the engine must implement a policy to evict pages when the memory pool becomes full. Common eviction policies include Least Recently Used (LRU) or Least Frequently Used (LFU), which prioritize the retention of pages that are most likely to be accessed in the near future. In the context of LLM inference, recency is a strong predictor of future access, as the attention mechanism heavily weights recent tokens. Therefore, LRU is often the preferred policy, ensuring that the most recent KV pages are retained while older, less relevant pages are evicted. When a page is evicted, its memory is returned to the free pool, making it available for new allocations. Defragmentation, in the context of paged memory, is less about moving data within the GPU memory (which is expensive) and more about managing the logical mapping of pages to physical slots.
