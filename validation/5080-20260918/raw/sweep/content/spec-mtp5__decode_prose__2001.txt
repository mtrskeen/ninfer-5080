In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the system divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory allocation allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which stores the key and value vectors for a specific number of tokens. The sizing of these pages is a crucial design parameter that directly influences the trade-off between memory overhead and fragmentation. Typically, a page might store the KV states for 16 or 32 tokens. If the page size is too small, the metadata overhead associated with tracking the physical location of each page becomes significant relative to the actual data stored, leading to increased memory pressure and slower index lookups. Conversely, if the page size is too large, the system suffers from external fragmentation and internal waste. For instance, if a sequence requires 17 tokens of KV cache and the page size is 32, the system must allocate an entire 32-token page, wasting 15 tokens worth of memory capacity. This "last page" fragmentation is the primary source of memory inefficiency in paged systems. Therefore, the optimal page size is a balance that minimizes the average wasted memory per sequence while keeping the table of physical page indices manageable. In practice, inference engines often use a page size that aligns with the GPU’s memory access patterns, such as multiples of the warp size or the L2 cache line size, to ensure that when a page is accessed, the data is fetched in a coalesced manner, maximizing memory bandwidth utilization.

The allocation strategy for these pages is governed by a block table, which maps logical page indices to physical page indices. When a new token is generated for a sequence, the inference engine checks if the current logical page is full. If it is, a new physical page is allocated from the free list, and the block table is updated to point the next logical page to this new physical location. This process is analogous to how an operating system allocates memory frames for a process. The key advantage here is that the physical pages do not need to be contiguous in GPU memory. This non-contiguity allows the inference engine to pack the KV caches of multiple sequences tightly together in memory, regardless of their individual lengths. This is particularly beneficial in continuous batching scenarios, where sequences of varying lengths are processed in the same batch. In a traditional contiguous allocation scheme, the batch size is limited by the longest sequence in the batch, as the memory allocator must reserve a contiguous block large enough to hold the KV cache of that longest sequence. With paged KV cache, the memory allocator can interleave the pages of shorter sequences into the gaps left by longer sequences, thereby increasing the effective batch size and improving GPU utilization. This leads to higher throughput, as the GPU can keep its compute units busy with more concurrent operations, amortizing the fixed costs of kernel launches and memory transfers over a larger number of tokens.

However, the introduction of paged memory introduces complexity in the attention computation itself. Standard attention kernels are optimized for contiguous memory access, where the keys and values for a given head are stored in a single, contiguous buffer. With paged KV cache, the keys and values for a single sequence are scattered across multiple physical pages. To handle this, the inference engine must implement custom attention kernels that can gather data from non-contiguous memory locations. These kernels typically iterate over the block table for each sequence, fetching the relevant key and value vectors from their respective physical pages and performing the attention computation in a fused manner. This requires careful optimization to ensure that the memory access patterns remain coalesced within each page, even though the pages themselves are scattered. Modern GPU architectures, such as NVIDIA’s Ampere and Hopper architectures, provide features like asynchronous memory copies and tensor cores that can be leveraged to hide the latency of these scattered accesses. Furthermore, the use of shared memory (or L1 cache) within the GPU cores allows the kernel to stage the data from the scattered pages into a local, contiguous buffer before performing the matrix multiplications required for attention.
