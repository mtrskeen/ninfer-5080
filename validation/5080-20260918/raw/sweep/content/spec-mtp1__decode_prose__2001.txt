In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the system divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory layout allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which stores the key and value vectors for a specific number of tokens. The sizing of these pages is a crucial design parameter that directly influences the trade-off between memory overhead and fragmentation. Typically, a page size is chosen to be a multiple of the number of attention heads and the head dimension, ensuring that the data layout is compatible with the GPU’s tensor core operations and memory coalescing requirements. For instance, if a model has 32 attention heads and a head dimension of 128, a page might store the KV data for 16 or 32 tokens. If the page size is too small, the metadata overhead associated with tracking the mapping between logical pages and physical pages becomes significant relative to the actual data stored, leading to increased memory pressure and slower index lookups. Conversely, if the page size is too large, internal fragmentation increases because the last page of a sequence may be only partially filled, wasting memory that could have been used for other sequences. Therefore, the inference engine must carefully calibrate the page size based on the specific model architecture and the expected distribution of sequence lengths in the workload. In practice, a page size that aligns with the hardware’s memory access patterns, such as being a multiple of 128 bytes or 256 bytes, is often preferred to maximize memory bandwidth utilization during the attention computation phase.

The allocation strategy for these pages is managed by a central memory allocator that maintains a free list of available physical pages. When a new request arrives, the engine allocates a logical page table for that request, which maps logical page indices to physical page indices. As the model generates tokens, the engine allocates new physical pages from the free list and updates the logical page table to point to them. This process is highly efficient because it avoids the need to copy or move existing data in memory, which would be prohibitively expensive on a GPU. The allocator typically uses a first-fit or best-fit strategy to select physical pages, though in the context of GPU inference, the primary concern is not minimizing external fragmentation in the traditional sense, but rather ensuring that there are enough contiguous physical pages available to satisfy the allocation requests for the active batch. Since the GPU memory is a flat address space, the physical pages do not need to be contiguous in memory; they can be scattered across the HBM. This flexibility allows the engine to pack the KV caches of multiple sequences tightly together, maximizing the number of concurrent requests that can be served within the available memory budget. The logical page table acts as an indirection layer, allowing the attention kernel to gather the scattered physical pages into a coherent logical sequence during the computation of attention scores.

Eviction and defragmentation in a paged KV cache system are handled differently than in traditional operating systems. In a single-GPU inference engine, the primary driver for eviction is the completion of a request. When a request finishes generating its output, its associated physical pages are returned to the free list. However, in scenarios where the memory is fully utilized and a new high-priority request arrives, the engine may need to preempt or evict active requests. This is typically done by swapping the KV cache of the preempted request to CPU memory or disk, a process known as offloading. The paged structure facilitates this offloading because the engine can copy individual pages to the host memory without needing to move the entire contiguous block. This granular offloading is significantly faster than moving large contiguous buffers, especially when the GPU and CPU memory are connected via a high-speed interconnect like NVLink or PCIe. Defragmentation, in the context of GPU memory, is less about compacting the memory to create large contiguous blocks (as in OS virtual memory) and more about maintaining a healthy free list.
