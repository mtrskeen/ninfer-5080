In the architecture of modern single-GPU large language model (LLM) inference engines, the management of the Key-Value (KV) cache represents one of the most critical bottlenecks for both memory efficiency and computational throughput. As transformer-based models generate tokens sequentially, the attention mechanism requires access to all previously computed key and value vectors to compute the attention weights for the current token. In a naive implementation, this results in a linearly growing memory footprint that is tightly coupled to the batch size and sequence length, leading to severe memory fragmentation and underutilization of the GPU’s high-bandwidth memory (HBM). Paged KV cache, a technique popularized by systems like vLLM, addresses these inefficiencies by borrowing concepts from virtual memory management in operating systems. Instead of allocating a contiguous block of memory for the entire KV cache of a sequence, the engine divides the cache into fixed-size blocks, or "pages," which are allocated on demand. This decoupling of logical sequence length from physical memory layout allows the inference engine to manage memory with significantly higher granularity, reducing internal fragmentation and enabling more efficient batching of concurrent requests.

The fundamental unit of this system is the KV page, which typically stores the key and value vectors for a fixed number of tokens, often referred to as the page size or block size. For instance, if the page size is set to 16 tokens, a single page in the KV cache will hold the key and value tensors for 16 consecutive tokens in the sequence. The choice of page size is a critical design parameter that involves a delicate trade-off between memory overhead and management complexity. A smaller page size, such as 1 or 4 tokens, provides finer granularity, which minimizes the amount of wasted memory at the tail end of a sequence (internal fragmentation). However, a smaller page size increases the metadata overhead required to track the mapping between logical pages and physical memory blocks. The inference engine must maintain a table that maps each logical page index to a physical memory address, and if the page size is too small, the number of entries in this table grows exponentially, consuming valuable memory and increasing the CPU-GPU synchronization overhead. Conversely, a larger page size, such as 64 or 128 tokens, reduces the metadata overhead and simplifies the memory management logic, but it increases the likelihood of internal fragmentation. If a sequence ends in the middle of a page, the remaining slots in that page are wasted. Therefore, most production-grade inference engines adopt a middle-ground approach, often using a page size that is a power of two, such as 16 or 32 tokens, to balance the cost of metadata management against the loss of memory efficiency. This sizing also aligns well with the memory access patterns of GPU kernels, as larger contiguous blocks of data can be fetched more efficiently by the memory controller, reducing the number of memory transactions required to load the KV cache into the compute units.

Page allocation in a single-GPU environment is managed by a central memory allocator that operates on a pool of pre-allocated physical memory blocks. When a new request arrives, the engine does not immediately allocate memory for the entire potential length of the response. Instead, it allocates pages incrementally as the model generates new tokens. This lazy allocation strategy is crucial for maximizing the number of concurrent requests that can be served within the fixed memory limit of the GPU. The allocator maintains a free list of available physical pages. When a new token is generated, the engine checks if the current logical page for that sequence is full. If it is, the allocator retrieves a new physical page from the free list and updates the logical-to-physical mapping table. This process is highly efficient because it involves simple pointer arithmetic and table lookups, which can be performed on the CPU with minimal latency, or even on the GPU if the metadata is kept in device memory. The key advantage of this paged approach is that it eliminates the need for contiguous memory allocation, which is a major source of fragmentation in traditional inference servers. In a non-paged system, if a long-running request occupies a large contiguous block of memory, subsequent shorter requests may fail to allocate memory even if there is sufficient total free memory, simply because the free space is fragmented into small, non-contiguous chunks. Paged KV cache solves this by allowing the physical memory to be scattered across the GPU’s HBM, as long as the logical sequence is correctly mapped to these scattered physical pages.

Eviction and defragmentation are the mechanisms by which the inference engine reclaims memory from completed or aborted requests to make it available for new incoming requests. In a paged system, defragmentation is largely unnecessary in the traditional sense because the memory is already managed in discrete blocks. When a request completes, the engine simply marks all the physical pages associated with that request’s logical pages as free and adds them to the free list.
